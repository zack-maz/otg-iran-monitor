# Redis Key Registry

Every Redis key the app reads or writes. This is the only copy of the list — `CLAUDE.md` and the other docs link here.

**Drift gate:** `src/__tests__/lib/redis-registry.test.ts` greps `server/` and `src/` for key-shaped literals and fails if a key in code is missing here, or a key here has no code reference. Add the row in the same commit as the code.

**Conventions**

- Values written through `cacheSetSafe` are wrapped as `CacheEntry<T> = { data, fetchedAt }` (`server/cache/redis.ts`). The _logical_ TTL is a read-time argument that decides `stale`; the _hard_ TTL is the Redis expiry and is what is listed below. Hard TTL is normally 10x logical so stale data outlives an upstream outage.
- TTL is a per-call argument, not a key property. Writers of a shared key must import the shared constant (`LLM_TERMINAL_TTL_SEC`, `WATER_REDIS_TTL_SEC`, `EVENTS_REDIS_TTL_SEC`) — a literal silently shortens the cache.
- Bump the version segment (`sites:v3`, `water:facilities:v4`, `geocode:fwd:constrained:v2:`) whenever a change alters the stored shape or filter behavior; otherwise the old cache hides the change for a full TTL.
- `CACHE_KEY_PREFIX` must be **unset** in production. It exists to namespace dev; set in prod it splits writers from readers.
- No file/line citations here on purpose — find a key with `grep -rn "'<key>" server/`.

## Known dead weight

Keys that exist in code but do no useful work today. See `docs/AUDIT-2026-09.md` for the cleanup plan.

- `events:llm:v3:group-lineage:{hash}` — reader without a writer.
- `llm:tokens:*` — reader without a writer on the active pipeline.
- `events:llm:v3:lineage:*`, `cron:watch:v2`, `events:llm-cost-shadow:*` — writers without a production reader (or, for cost shadow, pricing a free tier).
- `operator:*-quota:*` — per-Bearer quotas for a system with one Bearer holder.
