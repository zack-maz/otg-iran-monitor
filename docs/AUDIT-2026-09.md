# Audit — 2026-09-17

A point-in-time review of production, the codebase and the docs after ~12 weeks unattended (last deploy 2026-06-22). This file is a snapshot: fix things, tick them off, and delete it when the backlog is empty.

Method: live probes of https://otg-iran-monitor.vercel.app, Vercel logs, GitHub Actions history, a browser session, then three parallel read-only code audits (server, client, docs) whose claims were verified against code. Items marked _(unverified)_ were not confirmed against production.

**Status legend:** FIXED = fixed on branch `chore/overhaul-2026-09`, not yet deployed. OPEN = not addressed.

## 1. Summary

- **The product works, degraded.** Map, ships, events (raw GDELT), sites, water, weather, markets and news all serve. Two things were down: **flights (HTTP 500)** and **the LLM event pipeline (producing nothing for months)**. Both root causes are fixed on the branch.
- **The monitoring did not catch either.** Health showed the crons green throughout, because it measures "the scheduler ticked", not "the product has data". Both outages were found by looking.
- **The LLM pipeline is the problem area.** ~7k source lines and ~12k test lines wrap one daily batch job. It has at least four independent ways to finish "successfully" having written nothing, and about half of its machinery is inert or write-only.
- **The rest of the code is healthy but over-ceremonied.** 2,716 tests pass (19 skipped, 5 todo), `tsc` is clean, lint has 0 errors. Roughly 5k source lines and 8k test lines on the server, plus ~1k on the client, can be deleted with no loss to a single-operator dashboard.
- **Docs were ~17.8k lines across 49 files, contradicting each other and the code.** Now: `README.md`, `CLAUDE.md`, `docs/ARCHITECTURE.md`, `docs/OPERATIONS.md`, `docs/redis-keys.md`, this file, and the frozen ADRs.

## 5. Architectural flaws

1. **The most expensive artifact has the weakest durability.** One all-or-nothing write at the end of an unbounded job, through an error-swallowing helper, keyed by unstable ids, from input that only existed if a browser was open. Successive "simplify" passes removed safety nets (incremental flush, partial key) while "observability" passes added recorders that watch the wrong thing. Invert it: bounded, checkpointed, idempotent run; one honest outcome record.
2. **Health measures the scheduler, not the product.** Cron ticks, the cron watch and the eval score were green through ~85 cold days.
3. **Degrade-open everywhere, with no floor.** Swallowed writes, adapters returning `[]`, "silently skip failed downloads". Individually reasonable; together the system cannot tell "empty" from "broken". Minimum: swallowers log a warning; expensive writes throw.
4. **Work scales with the length of the war; budgets do not.** Backfill, extraction and both event blobs grow daily and are rewritten whole. Needs a rolling window and per-day keys.
5. **Heavy work on the request path** (events backfill, water precip → up to 540 s of Overpass). Crons should own slow upstream work; routes should be cache + snapshot only.
6. **The operator console is a quarter of the client** for a once-daily cron. After the pipeline is simplified, five operator endpoints reduce to `/api/health` plus one `/api/ops`.

## 6. Recommended order

1. **Merge and deploy the branch** (flights back; pipeline unblocked; limiter and logging fixed). Run `vercel build` locally first — the last long gap surfaced five stacked deploy blockers.
2. **Watch the first 04:00 UTC run.** Read the cron response `dispatched/reason`, then `llm:runs:history`. Expect L3 (timeout on a cold run). Fix L2 + L3 + L4 together: cap the run, checkpoint the write, record the real outcome, add the freshness health check.
3. **Green CI:** bump `maplibre-gl` (critical advisory), `npm audit fix` the rest, re-enable CodeQL, repair `check:env` and add it to CI.
4. **Pipeline diet (§4):** delete the inert machinery before touching L5/L6 — it is most of the surface area.
5. **Client:** one `usePolling` (fixes C1, C2), honest failure UX (C3), lazy-load the operator console (C6).
6. **Fetch helper (A6)** and typed upstream errors (A5).
7. Then decide whether the v2.0 load-test phases are still worth doing. Note the roadmap's premise for phase 47 is wrong: CDN cache headers already exist (`server/middleware/cacheControl.ts`, applied in `server/index.ts`); only the `s-maxage` values differ from the plan.
